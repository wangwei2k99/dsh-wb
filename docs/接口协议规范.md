# CodeBuddy 中国区接口协议与渠道修复

本文记录本插件实际发出的协议，以及 2026-10-28 把 `400 / 11128` 修掉的完整规则。
它是第三方对照记录，不是腾讯的官方 API 承诺。路径、请求头和名单会变；变了以后用同一套最小对照重测，不要按旧结论加替换。

更早的目录接口和模型字段见 [反向代理调用 WorkBuddy API 开发文档](./反向代理调用WorkBuddy-API开发文档.md)。
2026-10-21 的渠道取证见 [CodeBuddy 调用方式与渠道兼容分析](./2026-10-21-codebuddy-channel-analysis.md)。

## 1. 端点

| 用途 | 方法 | 地址 |
| --- | --- | --- |
| 模型与产品配置 | `GET` | `https://copilot.tencent.com/v3/config` |
| 推理 | `POST` | `https://copilot.tencent.com/v2/chat/completions` |

推理使用 OpenAI Chat Completions 形状，`stream: true`，响应为 SSE。
使用 `max_tokens`，不用 `max_completion_tokens`。
`model` 必须来自当前 Key 在 `/v3/config` 里、`agents[name=cli].models` 与 `data.models` 的交集。

API Key 同时放：

```http
Authorization: Bearer <API_KEY>
X-API-Key: <API_KEY>
```

登录令牌只放 `Authorization: Bearer <accessToken>`，不放 `X-API-Key`。
Key 不进 URL，不进日志。

## 2. 出站身份

API Key 走 CLI 身份。令牌登录走 WorkBuddy 桌面身份。两套都要带会话头族。

### 2.1 CLI（API Key）

| 头 | 值 |
| --- | --- |
| `User-Agent` | `CLI/2.171.0 CodeBuddy/2.171.0` |
| `X-Product` | `SaaS` |
| `X-IDE-Type` | `CLI` |
| `X-IDE-Name` | `CodeBuddy` |
| `X-IDE-Version` | `2.171.0` |
| `X-Requested-With` | `XMLHttpRequest` |
| `X-CodeBuddy-Request` | `1` |
| `X-Private-Data` | `true` |

### 2.2 WorkBuddy 桌面（令牌）

| 头 | 值 |
| --- | --- |
| `User-Agent` | `WorkBuddy/5.9.2 WorkBuddy/5.9.2 CLI/2.161.0` |
| `X-Product` | `SaaS` |
| `X-IDE-Type` | `WorkBuddy` |
| `X-IDE-Name` | `WorkBuddy` |
| `X-IDE-Version` | `5.9.2` |
| `X-Agent-Intent` | `craft` |
| `X-Agent-Purpose` | `conversation` |
| `X-Agent-Type` | `main` |
| `X-Domain` | `copilot.tencent.com` |
| `X-Requested-With` | `XMLHttpRequest` |
| `X-CodeBuddy-Request` | `1` |
| `X-Private-Data` | `true` |
| `X-User-Id` | 账号 user id，缺省 `anonymous` |

桌面身份另带链路头：`traceparent`、`b3`、`X-B3-TraceId`、`X-B3-SpanId`、`X-B3-Sampled`、`X-Trace-ID`。
主请求不带 `X-B3-ParentSpanId`。

调用方带入的 `x-stainless-*` 一律删除。`User-Agent` 被上面的身份头覆盖。

### 2.3 会话头族

聊天请求必须同时带这三项，缺任意一项是 `400 / 11128`，`msg` 为 `conversation id missing` 或 `request illegal`：

| 头 | 形状 |
| --- | --- |
| `X-Conversation-ID` | 带连字符的 UUID。同一会话多轮复用；由账号和会话键稳定派生 |
| `X-Conversation-Request-ID` | 32 位无连字符 hex。一轮内与 `X-Root-Request-ID` 同值 |
| `X-Conversation-Message-ID` | 32 位无连字符 hex。一轮内与 `X-Request-ID` 同值 |

调用方已经带了同名头时保留原值，不另造一套。

## 3. 请求体

```json
{
  "model": "deepseek-v4.1-flash",
  "stream": true,
  "max_tokens": 1024,
  "messages": [
    { "role": "system", "content": "You are CodeBuddy, Tencent's official CLI." },
    { "role": "user", "content": "只回复两个字：可以" }
  ]
}
```

`content` 可以是字符串，也可以是 `{ "type": "text", "text": "..." }` 数组。两种都改写。

`developer` 角色上游不接受，发出前改成 `system`。一条请求里因此可以有多条 `system`。

`assistant` 只改身份句，不改品牌词，不改 `@` 路径说明。`user`、`tool` 和 `tools` 原样转发。

## 4. 渠道名单与修复

上游对提示词做渠道指纹检查。命中时 HTTP 400，业务码 `11128`，`msg` 为：

```text
Illegal API invocation from an unapproved channel
```

插件把这条说成「提示词命中上游渠道名单（不一定在第一行）」，并附上第一条 system 的第一行。
这行只说明发出的开头，不说明命中点。开头已经是允许的身份句时，命中点在后文。

### 4.1 已证实会 400 的原文

同一套 CLI 头、同一把 Key、模型 `deepseek-v4.1-flash`，2026-10-28 对照：

| 请求里出现的文本 | 结果 |
| --- | --- |
| system 只有 `You are CodeBuddy, Tencent's official CLI.`，用户消息「只回复两个字：可以」 | 200，回复「可以」 |
| system 为 `You are an AI agent powered by DeepSeek Harness.`，另有 `developer` 角色的 Claude Code 身份句 | 400 / 11128 |
| 约 5 万字的 DSH 系统提示，身份句已换成 CodeBuddy，但仍含下一行的 `@` 路径说明 | 400 / 11128 |
| 同一份提示，只改 `@` 路径说明的起句 | 200，模型开始回复 |
| 用户消息里单独出现 `Current DeepSeek Harness implementation checkout` | 200 |
| `dsh headless` 短提示（系统提示较短，不含该 `@` 路径句） | 200 |

`@` 路径句的命中跨度是整句，不是其中半句。下面两句分开各发都是 200，连在一起是 400：

```text
Tokens prefixed with @ are paths the user explicitly referenced.
Relative paths resolve from the workspace root
```

去掉开头的 `Tokens`，或在 `workspace` 处截断，都回到 200。

此前试过、不能当修复的做法：

| 做法 | 结果 |
| --- | --- |
| 删掉身份句，前面补 `You are a helpful assistant.` | 短请求可以过；完整 DSH 提示仍因后文 400 |
| 前面补 `Follow the instructions below.` | 400。不以 `You are` 开头的占位句会被拒 |
| 只换第一行，留下 `@` 路径句 | 400。界面仍显示开头是 CodeBuddy 身份句 |

### 4.2 出站改写

`system` 和 `developer` 走完整改写。`assistant` 只改身份句和 `@` 路径句。顺序如下。

| 原文 | 换成 |
| --- | --- |
| `You are an AI agent powered by ...`、`You are a coding agent powered by ...`、`You are an AI assistant built on ...`，到该句句号或行尾 | `You are CodeBuddy, Tencent's official CLI.` |
| `You are Claude Code, Anthropic's official CLI for Claude.` | 同上 |
| 行首 `You are Claude Code` | 同上 |
| `main branch (you will usually use this for prs)` | `main branch (you will usually use this for pr)` |
| `Tokens prefixed with @ are paths`（system、developer、assistant） | `An @ prefix marks paths` |
| 行首 `You are interacting with the user through the ` | `The user is interacting through the ` |
| `DeepSeek Harness` / `DeepSeek-Harness` | API Key 为 `CodeBuddy`，令牌登录为 `WorkBuddy` |
| 独立大写 `DSH` | 同上 |

身份句和 `@` 路径句也用于 `assistant`。品牌词不用于 `assistant`。

改完为空时，补上 `You are CodeBuddy, Tencent's official CLI.`。
句前标记和句后指令保留，不再在最前面加中性占位句。

`@` 路径句改完是：

```text
An @ prefix marks paths the user explicitly referenced. Relative paths resolve from the workspace root
```

独立 `DSH` 的替换排除这些功能性写法，否则模型会拼错包名、路径或命令：

- `dsh-...`、`dsh_...`
- `@deepseek-ai/dsh-*`
- 路径里的 `.dsh/`
- 环境变量 `DSH_...`
- 命令 `dsh`

### 4.3 代码位置

| 行为 | 位置 |
| --- | --- |
| 提示词改写 | `index.js` 的 `rewriteChannelIdentity`、`sanitizeWorkBuddyRequest` |
| CLI / 桌面请求头、会话头族 | `workbuddy-auth.js` 的 `IDENTITY_CLI_HEADERS`、`IDENTITY_WORKBUDDY_HEADERS`、`conversationHeaders` |

桌面端加载的是 profile 里的安装副本，不是仓库工作区：

```text
%USERPROFILE%\.dsh\profiles\desktop\node_modules\@wangwei2k99\dsh-workbuddy
```

该 profile 的依赖是 `github:wangwei2k99/dsh-workbuddy`。只改仓库、不把 `index.js` 与 `workbuddy-auth.js` 拷进上述目录，正在运行的桌面端仍是旧逻辑。拷贝之后必须完整退出 DeepSeek Harness 再打开。进程内已经加载的模块不会自己更新。

## 5. `11128` 按 msg 分支

`11128` 和 `11-128` 是重载码。看 `msg`，不看码本身。

| `msg` | 含义 | 处理 |
| --- | --- | --- |
| `conversation id missing`、`request illegal` | 会话头族不齐 | 补第 2.3 节的三件套 |
| `Illegal API invocation from an unapproved channel` | 提示词里仍有渠道指纹 | 按第 4 节在整段 system 里找，不要只看第一行 |
| `first message is not system prompt` | 首条消息不是 system | 补 system，或把 `developer` 改成 system |

其它业务码：

| 码 | 含义 |
| --- | --- |
| `11140` | 账号被上游限制。重新登录或换 Key 无效 |
| `11115` | 上下文超限。错误文本带 `context_length_exceeded`，交给 DSH 压缩 |
| `11101` | 请求形态不被接受，该接口要求流式 |

## 6. 再出现 400 时怎么对照

1. 用同一把 Key、同一套 CLI 头，只发身份句加一句「只回复两个字：可以」。这条必须 200。它若 400，问题在头或凭据，不在提示词。
2. 把失败会话里的 system 原文经第 4.2 节改写后原样重放。仍 400 时，按行对半切，直到剩下最短的 400 片段。
3. 半句分开是 200、连在一起才 400 的，整句都算指纹，只改半句不够。
4. 新指纹加进 `sanitizeWorkBuddyRequest`，并在 `test.js` 里锁住改写结果。实网至少重放一次失败会话的 system。
